# Reports #259–#266: local investigation and fixes

September 30, 2026. These reports contain sanitized observations, not exact
commands or a verified common root cause. No private command or project data is
published. Existing analytics work remains in the working tree.

## Confirmed defects

Supported inspection prefixed with `set -e` was rejected by the inline-helper
entry check even though the helper validator already understood that option.
The resulting hook rewrite reserved workload capacity for simple file reads,
repository searches, Git status, SSM API reads, remote command-status calls and
even `memcap wait`. The latter can make an observation wait compete with work
whose completion it needs to observe.

The entry check now reaches the existing complete validator for option-prefixed
helpers. It still proves every stage and guards expanded external arguments.
Arbitrary builds, execution-capable ripgrep options, unknown shell options,
startup settings and interactive SSM sessions retain admission. Fake remote
commands prove single execution and preservation of stdout, stderr, `set -e`
and failure status. No remote operation is executed by these tests.

The runtime argument guard also failed to bind a nested session wait to its own
scope. A stale sibling key survived even when the outer guard had the correct
key. Guarded waits now use the shared session-binding logic and the installed
executable for bare `memcap` invocations, preserving operation when Homebrew
is absent from the tool's PATH. This changes no lease, ownership, cancellation
or admission policy.

The initial four-test suite failed eight assertions before the fixes and passed
afterward. Coverage also includes both agent hook schemas and cached runner
reclassification before any reservation. Codex's existing permission contract
is retained; the hook fixture explicitly supplies the applicable permission mode.

## Delivery verification

The single final review traced option-prefixed commands through the complete
validator and runtime argv checks, then traced session waits through binding and
executable resolution. It adds no execution permission or signal authority.

All 59 focused checks pass (5 new, 8 productivity, 5 shell helpers, 12 completion,
29 orphan recovery). The new Bats wrapper also passes. The first full suites each
failed their new wait-path check before executable resolution was corrected;
these are failures, not successful gate runs. The next isolated run passed the
new checks but failed an existing measurement fixture: its invalid-unit reading
was assigned to the third live PID, which could disappear between probes. The
two associated fixtures now use synthetic, stable PID rows, and both targeted
checks pass. Production measurement behavior is unchanged. The final normal
suite passed all 633 tests (exit 0). Grouped ShellCheck passed for all 55 shell
and Bats files, and all 26 individual Bash parses passed. The final isolated HOME /
no-Docker rerun also passed all 633 tests (exit 0). Logs are retained at
`/tmp/memcap-issues-259-266-final-normal.log` and
`/tmp/memcap-issues-259-266-verified-isolated.log`. Remote CI is unverified.

The two changed libraries are installed with originals backed up at
`~/.local/share/memcap/local-patches/2026-09-30-issues-259-266-095011`.
Installed/source bytes match. Installer fingerprints confirm unchanged policy,
pause marker and Claude/Codex profiles. The owner's runtime state switched to
active during this task and was preserved; no policy transition was made here.
A live option-prefixed Git status completed without workload admission. Doctor
passes for three profiles and nine enabled/trusted Codex hooks.
