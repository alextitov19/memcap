# September 24 feedback audit — v0.16.3

The release addresses the open reports #58–80. Reports describe observations,
not proven root causes; the distinctions below are part of their disposition.

## Evidence reviewed

Reviewed all available September 24 queue event segments, private ten-minute
observer intervals, actions, retained pressure snapshots, daemon stdout/stderr
changes, report drafts, job notices, and all 23 open GitHub issues with comments.
The frozen audit covers queue events from 08:03:23 to 21:04:00 local time and the
day's retained actions. Untimestamped daemon output before observer installation
cannot be assigned to a time window. Rotation/retention can erase older evidence;
this is not a claim of continuous measurement or complete pre-install history.
Raw evidence remains private; no commands, project identities or logs are published.

- 15,922 pressure samples: 9,432 yellow, 6,485 green, five red.
- 874 admissions, 861 completions; median admission wait 2.1065 seconds,
  maximum 5,044.521 seconds (about 84 minutes).
- Three logged degraded process snapshots; reporting-probe failures were not
  distinguishable from queue-sampler failures in the old public metrics.
- One recorded oversized-job action at 08:57:21: 4.33 GiB against the owner's
  4 GiB per-process setting, with a corresponding private agent notice. One
  orphan cleanup was recorded. Tier-three messages largely describe protection
  vetoes, not successful kills.
- Twenty completion events recorded `15`, but the old event writer used
  `abs(returncode)`. These cannot distinguish application exit 15 from SIGTERM,
  and they cannot all be attributed to the one oversized-job action.

## Reproduction and validation

`tests/test_feedback_release.py` first reproduced eight lightweight classification
failures and an incomplete-sample allowance dropping from 5 GiB to 1 GiB.
The corrected classifier admits these inspections without a workload reservation.
Tests preserve command substitution, executable sed, mixed build stages, malformed
redirection and subshells as managed work. Existing hook tests cover Claude and Codex.

The deterministic reservation replay holds a 5 GiB allowance for a historical
4 GiB peak while current usage is 0.25 GiB. It stays reserved through the first
60 seconds, then falls to 0.5 GiB after continuous fresh complete samples. A
2.88 GiB available-memory fixture changes from denied to admitted; red pressure
still denies it. Fresh growth to 6 GiB immediately reserves 7.5 GiB. Gaps,
incomplete samples, stale samples, explicit requests and strict policy cannot
use this decay. These are controlled policy results, not a real-world speedup
benchmark or a guarantee that later bursts cannot reach red.

Local release validation: shellcheck passed; all 24 shell files parsed individually
with bash 3.2; 608/608 Bats tests passed normally and 608/608 with an isolated HOME
and no Docker runtime. Twelve new Python regression tests passed. The one final
review found and corrected ANSI/translated quoting and same-sample growth edge
cases; their negative controls failed before those corrections. CI status is
recorded separately in the PR/release, not inferred from these local results.

## Upgrade behavior

New invocations through stable Homebrew hooks and newly started automatic wrappers
pick up the release. Existing running supervisors retain their loaded code.
Use `memcap integrate` to refresh installed managed guidance and metadata; preserve
all unrelated permissions/settings. Restart/reload a session when hook definitions
change, and review Codex trust in `/hooks` when required. Updating memcap cannot
prove a previously open session has reloaded its hooks. No Docker restart, policy
increase, pause/resume change or other project's process termination is required.
