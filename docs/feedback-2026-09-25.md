# September 25 feedback audit

Report #133 was a `find ROOT -name PATTERN | xargs wc -l` listing. v0.16.6
recognizes that filename search and sequential counting form. Other find actions,
child programs and xargs options remain managed. A pre-fix failure and real-shell
fixture verify the reported behavior. Report #132, by contrast, combined recursive
directory deletion with status inspection; it remains managed as a mixed workload.
That issue is closed as not planned with the boundary explained, not as a claimed fix.

Report #130 used a fixed shell helper that prints a five-line sed excerpt for
each literal file/line pair. v0.16.6 recognizes only that fixed body and up to
64 literal calls; function recursion, altered bodies, dynamic paths/lines and
additional workloads remain managed. The old classifier fails the regression;
the new one also has real-shell output and rejection controls.

Issue #131 was reproduced while intentionally canceling a superseded release
test. A process-identity query failed after launch, the supervisor exited 75, and
its test shell remained. Only that verified owned test group was cleaned up.
v0.16.6 retains supervision and reservations while retrying failed identity
observations, and retries unsuccessful guarded cancellation. Identity samples
are taken under the registry lock; retry delays release it. A synthetic test
injects an interrupted query, a query timeout, a cancellation timeout and a
failed cancellation before recovery. It verifies fresh locked observation,
released locks during retries, one launch, and retained unverified members.
Termination still uses the existing per-PID ownership checks and kill choke point.

Report #129 arrived at 12:02 PDT during v0.16.6 validation. Its repository
search piped output through a single read-only sed substitution containing
escaped slash delimiters. The narrow substitution recognizer did not accept
escaped delimiters and queued the whole pipeline. v0.16.6 consumes escapes in
pairs, retains the single-substitution boundary and rejects execution/write
flags, extra scripts and in-place edits. A regression reproduces the classification
failure before the fix and checks the actual sed output afterward. The earlier
local full run was canceled and superseded so final validation covers both fixes.

## Historical attribution and throughput

#88's 25-minute wait and #90's 4.33-GiB server termination were filed
retrospectively. The reporting version and current healthy snapshot do not
identify the runner or host state at the earlier incident. The 4.33-GiB event is
documented in the September 24 audit against the configured four-GiB per-process
limit; no new termination appears in today's action log. This release does not
weaken that policy or claim an unexplained kill was repaired.

During release validation, a live job held about 4.1 GiB of allowance after its
measured usage dropped to about 50 MiB. Repeated stale cache reads erased its
fresh reservation window, preventing old peaks from retiring and delaying new
work. The new regression interleaves fresh samples with stale reads. Stale reads
retain the existing allowance and history without advancing either; fresh samples
still enforce continuity, and incomplete measurements/owner loss remain closed.
This directly addresses a reproduced starvation mechanism associated with #88.

The audit expanded to include #97–102 as they arrived, for 21 reports total.

## Suggestions assessed

Commands are already classified stage by stage; a pipe alone is not the cause.
Extend supported forms rather than treating arbitrary scripts, Git hooks or all
cloud transfers as small. Persistent resources still count toward memory.
Browser tests remain finite managed jobs because network waiting does not prove
small memory demand; adaptive reservations use physical-footprint observations,
not RSS. `gh run watch` is already native inspection. Use native completion
notifications for long waits; the bounded fallback now reports phase and age.
No raw output or free-text report upload was added. Fixed symptoms provide useful
detail within the existing one-time consent and privacy contract.

## Validation and rollout

Release verification results are recorded in the release notes. New commands use
the installed runner. Existing supervisors keep loaded code and classification.
Managed guidance and stable hook paths are refreshed by integration; unavailable
Codex runtime trust is reported as unverified. No Docker restart, live policy
write, lease deletion or process cleanup is part of this release.

### Later capacity finding (#124)

The next report arrived at 11:32 PDT. A new regression reproduced an adaptive
allowance rising from 512 MiB to the original 1 GiB solely because the sampler was
busy. The same base calculation affected faulty/incomplete observations. Retain
the previous effective automatic allowance instead. This releases no capacity
from unavailable evidence: admission still refuses a busy/faulty host sample,
complete fresh measurements alone can shrink, and observed growth increases the
allowance. Explicit, strict and orphaned floors are unchanged. A behavioral test
shows contention followed by a valid host sample with changing group membership
no longer invents an extra headroom deficit. This is a demonstrated defect, not
proof that it explains every long wait in #124.
