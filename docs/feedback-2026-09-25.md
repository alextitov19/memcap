## Historical attribution and throughput

#88's 25-minute wait and #90's 4.33-GiB server termination were filed
retrospectively. The reporting version and current healthy snapshot do not
identify the runner or host state at the earlier incident. The 4.33-GiB event is
documented in the September 24 audit against the configured four-GiB per-process
limit; no new termination appears in today's action log. This release does not
weaken that policy or claim an unexplained kill was repaired.

During release validation, a live job held about 4.1 GiB of allowance after its
measured usage dropped to about 50 MiB. Repeated stale cache reads erased its
fresh reservation window, preventing old peaks from retiring and delaying new
work. The new regression interleaves fresh samples with stale reads. Stale reads
retain the existing allowance and history without advancing either; fresh samples
still enforce continuity, and incomplete measurements/owner loss remain closed.
This directly addresses a reproduced starvation mechanism associated with #88.

The audit expanded to include #97–102 as they arrived, for 21 reports total.
Their later snapshots are separate from the initial-window statistics above.

## Suggestions assessed

Commands are already classified stage by stage; a pipe alone is not the cause.
Extend supported forms rather than treating arbitrary scripts, Git hooks or all
cloud transfers as small. Persistent resources still count toward memory.
Browser tests remain finite managed jobs because network waiting does not prove
small memory demand; adaptive reservations use physical-footprint observations,
not RSS. `gh run watch` is already native inspection. Use native completion
notifications for long waits; the bounded fallback now reports phase and age.
No raw output or free-text report upload was added. Fixed symptoms provide useful
detail within the existing one-time consent and privacy contract.

## Validation and rollout

Release verification results are recorded in the release notes. New commands use
the installed runner. Existing supervisors keep loaded code and classification.
Managed guidance and stable hook paths are refreshed by integration; unavailable
Codex runtime trust is reported as unverified. No Docker restart, live policy
write, lease deletion or process cleanup is part of this release.
